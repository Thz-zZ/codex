# Codex Relay Lite 源码

这个目录就是轻量版的完整源码项目：`src/` 放 C# 桌面程序，`ui-src/` 放界面文件，`session-backend/` 放随附的会话数据服务，`tests/` 放桌面界面测试。构建与运行均不依赖原 CodexSessionManager 项目目录。

## 构建

在 Windows PowerShell 中运行 `build-dev.ps1`。脚本使用 .NET Framework C# 编译器、WebView2 .NET SDK、Nett 和 Roslyn。默认从项目目录的上一级寻找 `native-toolchain/`；也可通过 `CODEX_RELAY_TOOLCHAIN` 指向依赖目录。WebView2 Runtime 需要安装在 Windows 上。

`CodexRelayLite.csproj` 可通过 MSBuild 属性 `RelayToolchainRoot` 指定同一依赖目录。

会话服务构建需要 Python 3.12+ x64，在独立虚拟环境安装 `session-backend/requirements-dev.txt`。通过 `CODEX_SESSION_PYTHON` 指定 Python 路径；`build-dev.ps1` 会自动调用 `build-sessions.ps1` 生成会话服务。发布后无需 Python 或 Qt。

## 版本与应用打包

当前版本为 **v1.2.7**，更新内容见 `CHANGELOG.md`。版本定义位于 `src/AppVersion.cs`，构建时自动同步到应用界面和 EXE 文件属性。

运行 `build-release.ps1` 生成可直接运行的 Windows x64 应用文件夹。可通过 `-OutputDirectory` 指定新输出目录。发布包包含应用与会话服务 EXE、DLL、界面、许可、会话管理说明及版本记录。

自动更新发布步骤见 [UPDATE-GUIDE.md](UPDATE-GUIDE.md)。程序默认从 `Thz-zZ/codex` 的 GitHub 正式版检查更新；发布脚本同时生成完整 ZIP 和 `update.json`。

本机程序正在运行时，可用 `build-dev.ps1 -OutputDirectory build/update-dev` 在独立目录编译；对应打包命令为 `build-release.ps1 -BuildDirectory build/update-dev`。新目录也需要先构建或复制未变更的 `SessionBackend.exe`。

## 内容

- `src/`：原生窗口、托盘、配置存储、NewAPI/Sub2API 查询和本地设置。
- `ui-src/`：中转列表、详情、缓存图表、编辑表单和样式。
- `session-backend/`：来自 CodexSessionManager v1.1.1 的本地会话引擎、私有 JSON 桥接及隔离测试。
- `tests/`：隔离的模拟接口与 smoke 测试。
- `THIRD-PARTY-NOTICES.txt`：随附组件和代码的许可说明。

## 多模型中转

原“自定义中转”更名为“Codex”，并提供 Claude、Grok、DeepSeek、通义千问、智谱 GLM、Gemini 模型类型。所有类型都沿用原有第三方中转方式：填写中转站提供的 API 地址、调用密钥和模型 ID，不预填官方地址，也不要求官方账户或官方密钥。

模型类型只用于分类，不限制中转站地址、模型名称或统计接口，也不会自动选择调用协议。新增中转时，模型类型、模型调用协议、默认模型三项为空并标明“必选”，需要逐项手动选择；默认推理强度可选，不指定时跟随 Codex；指定后仅作默认，不锁定其他强度选项。切换类型保留已填写的中转地址、API 密钥、自定义名称、协议、模型及账户配置。编辑已有记录恢复已保存的选择；历史记录未保存过的类型需要补选。已有记录的地址不会被自动修改。

调用协议以中转站的说明为准，与模型类型分开选择：

| 中转站提供的接口 | 调用方式 |
| --- | --- |
| `/v1/responses` | Responses 直接连接，任何模型类型均可使用 |
| `/v1/chat/completions` | Chat Completions 本地桥接 |
| `/v1/messages` | Claude Messages 本地桥接 |

填写中转站的 API 密钥，点击“获取模型”读取该密钥可见的全部模型，再从列表中明确选择默认模型，按需调整推理强度，保存并点击“应用”。获取列表不会自动代选默认模型；不能把列表外的名称作为默认项。新增中转必须先获取列表，导入当前配置也先打开草稿供确认。编辑时可复用已保存列表，地址、协议或 API 密钥变更后必须重新获取；列表变化时可主动重新获取并应用。API 地址中的自定义部署路径会保留。余额与用量查询默认自动识别，也可指定 NewAPI、Sub2API 或不查询统计，不随模型类型改变。

重新获取并保存列表的中转不再锁定单个模型：所选默认模型仅决定 Codex 的初始项，Codex 内可直接切换已应用列表中的其他模型。桥接按请求选择转发，未提供模型时才使用默认项；列表外的旧会话模型明确报错，不悄悄替换。旧的单模型记录和历史路由保留固定模型行为，编辑时获取列表、保存并应用即可升级。修改记录后仍需点击“应用”才会创建新路由，旧路由及配置备份不会被改写。Responses 直接连接不改写请求。

查看图片等工具返回的图片也会传给上游：Chat Completions 的工具消息只允许文本，因此在整组工具结果之后附加带调用标识的用户图片消息；Claude Messages 则转换为原生 `tool_result` 内的图片块。实际识图能力仍由所选模型和中转站决定。

“暂停自动刷新”会保存到本机设置，同时暂停窗口内及托盘后台的后续定时查询，重开窗口或重启后仍保留；不会中止已发出的请求，也不影响“刷新数据”手动查询。手动刷新会显示正在刷新及完成/失败提示。

应用中转时，使用 Codex 官方支持的 `model_catalog_json` 登记完整已获取列表，显示名与模型 ID 一致，默认模型优先排列，不再只显示一个模型或“自定义”。界面搜索一次最多显示 200 项，但保存及同步包含全部模型。默认推理强度不再锁定 Codex 的强度选择：不指定时不写入默认强度，由 Codex 选择；指定后写入默认档位，同时保留其他强度选项。Responses 目录保留 low、medium、high、xhigh、max、ultra 全部六档，桥接提供当前支持的 low、medium、high。目录选项不代表中转已验证支持，请按模型实际能力选择。列表不保证其中每个模型都支持所选协议、工具或推理强度，请以中转说明为准，必要时分别配置不同协议的中转。Codex 在启动时加载目录，应用后需重启 Codex；默认项不会强制重置旧会话的模型选择。配置文件或配置档案中的更高优先级设置仍可能覆盖用户级目录。

模型目录采用通用编码工具兼容元数据，保存于应用数据目录的 `model-catalogs/`，不包含地址或密钥，也不改写 Codex 安装文件和内置模型缓存。每种内容使用独立的哈希文件名，不覆盖旧目录；恢复配置备份时，原来的目录引用仍有效，用户原有目录文件保持不动。模型的具体能力和上下文上限不由显示名保证。上下文元数据使用 Codex 兼容客户端预算：272000 Token、有效比例 95%，不是对中转实际模型容量的承诺；已有目录中的独立上下文预算及 config.toml 的 model_context_window 覆盖保留。上下文用量来自真实请求，需在 Codex 重启并产生有效用量通知后显示；空会话或未报告用量时不伪造占用。

从 v1.2.7 起，启动时自动升级当前配置引用的本应用旧模型目录，补齐推理强度与上下文数据；仅替换该目录路径，保留当前模型、强度、密钥、上下文覆盖和未应用的中转编辑，并保存加密配置备份。不覆盖旧快照、外部用户目录或哈希已不匹配的文件。升级后仍须重启 Codex 加载目录。

桥接监听 `127.0.0.1`，将 Codex 的 Responses 请求转换成上游 Chat Completions 或 Claude Messages，支持流式文本、图片、函数工具、自定义工具及工具命名空间、多轮工具结果。Claude Messages 协议使用 `x-api-key` 和 `anthropic-version` 认证，包括模型列表与连通性测试；支持原生 JSON Schema 输出。Claude 的 low、medium、high 原样发送为 `output_config.effort`，与 JSON Schema 合并保留；不换算成思考 Token 预算，不强制开启旧模型的扩展思考。兼容中转返回的流式及 JSON `thinking`、分片签名和 `redacted_thinking` 内容；思考块及签名通过 Windows DPAPI 加密保留，工具续传时恢复原始块，不作为普通回复或明文思考输出。Chat Completions 支持推理内容续传，所有模型类型均按所选协议将 low、medium、high 原样发送为 `reasoning_effort`，需要中转站和模型支持。新列表模式按 Codex 所选模型转发；旧固定路由仍忽略会话模型选择。所有桥接模式的强度均优先采用 Codex 当前请求的选择，未提供时才使用中转的默认强度。不支持的档位或上游参数错误明确报错，不重试为较低档位或偷偷移除参数。所有协议均可选择“跟随 Codex（不指定默认强度）”，无需手动指定；未填写时保存接口也按此处理（内部仍使用 `default`）。应用该选项会清除配置中遗留的默认推理强度，不会将 `default` 写成 Codex 推理强度或发送给桥接上游；仅当 Codex 请求和中转默认均未提供强度时，桥接才省略强度参数。旧记录可继续读取，编辑时保留已保存的默认强度；未保存强度的记录跟随 Codex。

提示词缓存采用适用于全部中转的统一策略，不提供开关：依赖中转或模型服务的自动提示词缓存，桥接不再注入 Claude 专用 `cache_control`，也不盲目注入其他协议的缓存键或有效期字段。Responses 直连仍原样传递 Codex 请求，不拦截或改写原生缓存字段。本机不缓存完整回答、提示词或工具执行结果，不复用旧答案；请求始终正常发送给上游。缓存命中可能降低重复输入的费用与延迟，但不减少实际输出 Token；实际优惠、支持范围、前缀长度与有效期由中转决定，不保证命中。不支持自动缓存、必须显式提供专用标记的服务，在此策略下可能没有缓存。尽量保持模型、强度、工具定义及重复前缀稳定。

统一缓存策略在设置页展示，不再针对 Claude 或其他单个模型展示缓存开通承诺、固定有效期或最近一次请求的专用缓存面板。详情区保留模型参数和实际发送的模型、强度；缓存命中率、读取和写入继续来自中转用量统计。桥接仍正常解析上游真实返回的缓存 Token，未知与真实 0 区分，不将写入或未命中量冒充读取命中，不伪造节省量；计数不会改变请求或引发额外生成调用。

具体能力取决于所选模型及服务权限。桥接暂不提供 Codex 原生联网搜索、音频、服务端代码执行或 `previous_response_id` 状态续传；默认联网搜索工具不会发送给上游，其他不支持的请求会明确报错。

使用桥接时需保持 Codex Relay 运行，可收起到托盘；退出后模型调用停止，重新打开时使用原端口和凭据恢复。Codex 配置只写入本地地址及本地凭据，上游密钥和桥接路由保存在应用数据目录的 `model-bridge.json`，密钥由 Windows DPAPI 加密。最多保留最近 16 份已应用的路由配置；删除中转时同步删除它的桥接凭据记录。原有 Responses 中转继续直接连接。

也可手动填写官方 API 地址直连，但本应用不再为模型类型绑定官方地址；官方余额接口与 NewAPI/Sub2API 不通用，此时可另选“不查询统计”。这不影响模型调用。

发布的源码压缩包不包含生成的 EXE、真实 Codex 配置、API 密钥、本机缓存或运行时依赖包。在本地构建或测试后，项目内会生成 `build/` 和 Python 缓存目录。

## 上传 GitHub

根目录的 `.gitignore` 已排除 `build/`、编译输出、Python 缓存与虚拟环境。源码、界面、构建脚本、测试和第三方许可仍可正常提交。

忽略规则不会删除磁盘上的文件，因此 VS Code 资源管理器中仍可能看到 `build/`；它不会被 `git add .` 加入提交。可运行 `git status --short --ignored` 查看，`!! build/` 表示已忽略。

会话使用说明见 `SESSION-GUIDE.md`。导入与永久删除需要关闭其他 Codex 客户端；不会自动关闭这些客户端。

## 内存管理

详情响应缓存最多保留 24 份，序列化 UTF-16 数据预算为 4 MiB，单份上限为 1 MiB；这些是缓存数据预算，并非进程实际堆内存上限。旧查询按最近使用顺序淘汰，各中转筛选设置独立保留，缓存淘汰后仍需手动刷新。磁盘快照仅在页面初始化时读取，查询响应不再重复携带本地历史。关闭窗口只收起到托盘，不销毁或重新加载 WebView2，重开保留原页面、筛选、滚动位置和未保存草稿，因此后台会保留界面内存。隐藏时仅原生后台定时器执行自动统计刷新，避免界面重复查询；模型桥接继续运行。空闲会话服务仍会释放，后续操作按需启动；完全退出请右键托盘图标选择“退出”。

接口响应直接使用现有缓冲区解码，用量汇总减少临时集合；超过 256 条的 NewAPI 日志在后台线程处理。会话列表每次刷新只扫描一次本地数据，长会话预览共享去重集合，仅保留当前分页和最近一次可重试响应，避免旧分页持续累积。

## 验证

运行 `tests/test-model-bridge.ps1 -ToolchainRoot <依赖目录>` 验证协议转换、流式 HTTP、密钥隔离、配置应用及重启恢复，并使用本机 Codex CLI 与模拟上游完成函数工具、自定义工具和推理续传的端到端测试。可通过 `-CodexPath` 指定 CLI。测试使用 build 内的独立配置与合成密钥，不访问真实模型服务或修改用户的 Codex 配置；实际服务可用性需要用户自己的 API 密钥验证。

运行 `node --test tests/detail-cache.test.cjs` 验证缓存淘汰、容量计算及大量查询下的数据保留上限。

使用会话虚拟环境运行 `python tests/measure-memory.py "build/Codex Relay Lite.exe"`，可执行隔离桌面 smoke 并采样主程序及全部子进程的工作集和私有内存，结果写入对应构建目录的 `smoke-data/process-memory.json`。工作集合计可能包含共享页，不能直接当作唯一物理内存用量。

使用会话虚拟环境运行 `python -m pytest session-backend/tests -q`。桌面测试先运行 `python tests/seed-session-fixture.py` 创建 build 内的合成会话，再执行 `build/Codex Relay Lite.exe --smoke-test`；运行 `node tests/generate-fixtures.cjs` 后，可通过 `--self-test` 验证原有中转逻辑。期望值来自独立旧版参考快照，生成时仅平移日期，无需其他项目目录。测试不操作真实用户会话。
