# Codex 中转台 源码

这个目录就是轻量版的完整源码项目：`src/` 放 C# 桌面程序，`ui-src/` 放界面文件，`session-backend/` 放随附的会话数据服务，`tests/` 放桌面界面测试。构建与运行均不依赖原 CodexSessionManager 项目目录。

## 构建

在 Windows PowerShell 中运行 `build-dev.ps1`。脚本使用 .NET Framework C# 编译器、WebView2 .NET SDK、Nett 和 Roslyn。默认从项目目录的上一级寻找 `native-toolchain/`；也可通过 `CODEX_RELAY_TOOLCHAIN` 指向依赖目录。WebView2 Runtime 需要安装在 Windows 上。

构建产物固定保存在 `build/current/`，以后持续复用这一目录，不再为不同版本、日期或验证新建一套构建。源码、编译参数及依赖没有变化时，应用和更新器直接复用已有 EXE；会话服务也只在源码更新或 EXE 缺失时重新构建。

`CodexRelayLite.csproj` 可通过 MSBuild 属性 `RelayToolchainRoot` 指定同一依赖目录。

会话服务构建需要 Python 3.12+ x64，在独立虚拟环境安装 `session-backend/requirements-dev.txt`。通过 `CODEX_SESSION_PYTHON` 指定 Python 路径；`build-dev.ps1` 会自动调用 `build-sessions.ps1` 生成会话服务。发布后无需 Python 或 Qt。

## 版本与应用打包

当前版本为 **v1.2.9**，更新内容见 `CHANGELOG.md`。版本定义位于 `src/AppVersion.cs`，构建时自动同步到应用界面和 EXE 文件属性。

运行 `build-release.ps1` 生成可直接运行的 Windows x64 应用文件夹。程序固定放在 `release/current/`，ZIP 和 `update.json` 固定放在 `release/assets/`，本地只保留当前一套。重复打包会替换这两个目录中的上一份产物，旧目录送入回收站，不累积版本文件夹或旧 ZIP。发布包包含应用与会话服务 EXE、DLL、界面、许可、会话管理说明及版本记录。

自动更新发布步骤见 [UPDATE-GUIDE.md](UPDATE-GUIDE.md)。程序默认从 `Thz-zZ/codex` 的 GitHub 正式版检查更新；发布脚本同时生成完整 ZIP 和 `update.json`。

程序占用输出文件时，先退出该目录中的程序再构建，继续复用固定目录。`-OutputDirectory`、`-BuildDirectory` 仅用于明确要求的自定义导出，不用于累积历史版本；覆盖已有发布目录前会校验发布标记、源码与构建路径隔离，以及目录链接。桌面导出仅在用户要求时执行。

## 内容

- `src/`：原生窗口、托盘、配置存储、NewAPI/Sub2API 查询和本地设置。
- `ui-src/`：中转列表、详情、用量记录、编辑表单和样式。
- `session-backend/`：来自 CodexSessionManager v1.1.1 的本地会话引擎、私有 JSON 桥接及隔离测试。
- `tests/`：隔离的模拟接口与 smoke 测试。
- `THIRD-PARTY-NOTICES.txt`：随附组件和代码的许可说明。

## 余额与本地用量

详情页的总成本、Token 缓存命中率、缓存读取 Token、本地用量记录和明细共用一套本地数据、日期与模型筛选及同步状态。切换左侧中转只改变中转名称和操作入口，不重查、不替换本地统计。右侧“同步”只读取本地 Codex Token 记录，完成后显示新增记录、扫描文件和错误数量；服务首次扫描显示载入数量，之后按新增记录计数，日期或模型筛选不计为新增。

启用余额查询后，每 5 分钟静默查询使用中中转，左侧中转旁的刷新图标可手动查询该中转余额。全局本地记录每 1 分钟按当前日期、模型筛选静默读取，也可点击右侧“同步”立即刷新。两套定时器独立，余额刷新不改写本地记录、同步结果或时间，本地刷新不查询余额，也不推迟余额定时器。自动同步不显示倒计时，成功时不弹提示，本地读取失败在详情保留错误状态和上次成功数据。已移除暂停按钮，自动同步持续运行；右侧“同步”使用普通按钮样式。收起到托盘后，原生定时器继续分别调度余额和本地记录。切换日期和模型只读取本地，不请求中转日志。NewAPI 不再下载 `/api/log/token`，额度换算信息在进程内缓存；Sub2API 优先使用账户余额接口，没有可用账户令牌时从 `/v1/usage` 组合接口只提取余额。

Token 与缓存命中率来自会话设置所选 Codex 目录的 `sessions/`、`archived_sessions/`，支持 JSONL 和 Zstandard 压缩日志，按北京时间筛选。统计覆盖全部本地会话，**不能按具体中转归属拆分**，切换中转不改变统计范围；左侧余额仍按中转分别显示。明细仅展示时间、模型、输入 Token、输出 Token、缓存读取和缓存率六列。本地用量无法提供可靠的 HTTP 状态，因此不再展示状态列；实际 HTTP 请求数不推算。日志提供的缓存写入 Token 仍参与本地成本估算。

详情第一张卡片显示所选日期和模型的“总成本”，与其他统计卡片统一使用无颜色高亮的样式。总成本是 USD 本地估算：普通输入、缓存读取、日志明确提供的缓存写入及输出分别按单价计算，不重复计算缓存与推理 Token，**不代表中转实际扣费**。优先只读使用 Codex 数据目录的 `relay-model-pricing.json`，其次使用用户目录的 `.cc-switch/model-pricing.json`，最后使用随程序内置的 CC Switch 价格快照（2026-11-02）；同步不会在线更新价格。价格表格式沿用 CC Switch 的 `models` 数组，每项为 `modelId` 和 `inputCostPerMillion`、`outputCostPerMillion`、`cacheReadCostPerMillion`、`cacheCreationCostPerMillion`，单位 USD / 百万 Token。模型 ID 精确匹配；存在缺少单价的模型时总成本显示“—”并标明数量，空用量显示 0，不把未知费用当作 0。悬停卡片说明可查看价格来源与缺失模型。

会话服务缓存每个文件的小时汇总和近期记录，后续读取只处理新增的完整行；相同累计 Token 事件和同一会话的归档副本不重复累计。逐条明细最多展示 300 条近期记录，汇总包含完整有效记录。刷新失败保留并标记上次成功的数据；收起到托盘后释放会话服务，下次打开按需重新读取。

## Codex 专用中转

本应用只管理 Codex，固定使用 **Responses 直接连接**。添加及编辑表单直接从中转名称开始，不再显示模型类型、调用协议或重复说明，也不再包含 Claude、Grok、DeepSeek、通义千问、智谱 GLM、Gemini 类型或 Chat Completions / Claude Messages 本地桥接。前端请求和后端保存、应用、获取模型、连通性测试均遵守这一限制；不支持的旧类型或协议会在发送请求或修改配置前明确报错。

添加中转的入口位于左侧顶部品牌栏右侧的“＋”图标，原来的大号添加按钮已移除；“我的中转”右侧仍可导入当前 Codex 配置。

右键左侧中转卡片可编辑、应用到 Codex 或删除，菜单带轻微淡入缩放动效，也可用 Shift + F10、方向键和 Escape 操作。右侧本地统计直接从筛选工具栏开始。只有使用中的中转显示浅色背景和细边框，点击查看不增加高亮；使用中按当前 Codex 配置地址识别，同地址有多条记录时优先按密钥区分。

填写支持 Codex Responses 的中转 API 基础地址、调用密钥和中转名称即可保存，**获取模型可选**。未获取时使用 Codex 自带的模型列表和默认模型，应用时清除此前的自定义模型目录及默认模型覆盖。点击“获取模型”后使用密钥可见的完整列表，并要求从中明确选择默认模型，不自动代选、不接受列表外的名称；可点击“使用内置默认”恢复。默认推理强度仍可选，不指定时跟随 Codex。模型 ID 由中转返回，不额外插入模型或容量预设；请确认上游支持所用模型。应用只把配置写入 Codex，不在本地代理、转换或拦截生成请求；退出本应用不影响已配置的 Codex 直连调用。

地址、API 密钥变更后编辑器会恢复内置默认，也可重新获取列表。编辑现有 Codex 记录可复用已保存列表，变更默认模型无需重新查询。使用获取列表时，应用中转写入 `model_catalog_json` 完整模型目录，显示名与模型 ID 一致，默认项优先排列；界面搜索一次最多显示 200 项，但保存及同步不截断列表。应用后需重启 Codex 或开启 CLI 新会话，旧会话不会被强制重置模型。指定的默认强度只作用于选中的默认模型；选择“跟随 Codex”会清除遗留的 `model_reasoning_effort`，不会写入无效的 `default` 值。已知模型沿用本机 Codex 声明的推理档位；不能将未声明的强度设为该模型的默认值。未知别名仅保留明确指定的默认强度，不额外声明六档全部支持。

自定义模型目录采用 schema v4，使用独立内容哈希快照，不包含地址或密钥，不修改 Codex 安装文件或内置缓存。优先离线读取本机 `codex debug models --bundled` 原生目录，旧客户端可只读回退到 `models_cache.json`。精确匹配的模型保留原生提示词、工具能力、上下文预算和推理档位；未知别名使用最小兼容条目，不推断容量、图片输入或工具能力。内置模式完全使用 Codex 自带元数据。启动迁移会去掉旧版统一 272000 / 95% 模板和 500k 预设，保留独立预算及用户的 `model_context_window` 覆盖。上下文用量来自原生真实 Token 通知，空会话或未报告用量时不伪造占用。

获取模型仅保存模型 ID，不读取或套用中转接口中的上下文容量，也不再添加“6.1 Sol · 500k”预设。旧记录重新保存或应用时使用普通模型；启动升级本工具管理的旧目录时，会还原普通显示名并采用可用的原生元数据，保留加密备份、独立预算和用户手动的全局窗口覆盖。

启动时安全升级当前 Responses 直连配置引用的本应用旧模型目录：保存加密配置备份，仅替换目录引用，保留模型、默认强度、上下文覆盖、注释和未应用的中转编辑。旧快照不覆盖；外部目录、哈希不匹配或损坏的目录、链接路径、旧桥接和非 Responses 配置不自动升级。升级后需重启 Codex 加载目录，配置备份可恢复原始目录引用。

### 配置保留与登录兼容

切换只更新模型与路由所需的字段，保留无关配置、注释、多行字符串和数组；支持引号键、内联表和子表。重新应用同一中转时保留高级设置；不同中转的请求头、重试与超时设置分别加密保存，切回时恢复，避免把上一家的私有请求头带给另一家。指定 API 密钥时清理会抢占认证的旧 `env_key`、认证命令及 Authorization 头。

第三方密钥始终写在当前 provider 的 `experimental_bearer_token` 中，不写入 `auth.json`。存在原生 ChatGPT 登录时保留登录文件并启用相应兼容标记；没有官方登录时保持独立 API 密钥模式。切换前保存加密备份并在提交前检查配置是否被其他程序修改，发现冲突会中止本次覆盖。配置文件变化时静默刷新“使用中”，窗口恢复或重新激活时也会核对。模型目录需要客户端重新加载，已有会话不会被强制重置。

左侧固定提供“OpenAI 官方”入口，与中转一样通过右键菜单选择“应用到 Codex”切回内置官方服务及默认模型，使用中可选择“重新应用”；普通点击打开本地统计，不切换配置。切换前保存加密备份，清除根配置及当前内联 profile 中的中转模型覆盖和官方端点重定向；其他 profile、项目、MCP 及全局偏好保留。登录文件和已保存的中转保持原样，切回中转可恢复其高级设置。官方模式不查询任何中转余额，本地用量统计继续共用，即使没有保存任何中转，也可查看、手动同步和自动同步本地记录。切换后需重启 Codex；尚未登录时在 Codex 中完成登录，本工具不代办登录或管理多个官方账号。

编辑窗口的“测试生成”与余额查询独立，仅手动点击时按表单地址、API 密钥、模型和推理强度发送一次短文本 Responses 请求，可能产生少量费用。未获取模型时，从本机 Codex 内置目录中选择可用模型，并在结果中显示实际测试模型；获取列表后使用所选模型。测试请求不写入 Codex 配置或保存中转，禁用远端存储，输出上限为 512 Token、总超时为 30 秒，不自动重试。结果区以颜色区分成功、警告和失败，显示 HTTP 状态及耗时；只有收到完成事件和有效文本才确认流式生成成功，非流式响应单独提示，未完成或空响应不会当作成功。测试仅验证短文本生成，工具调用仍需在 Codex 中验证。

### 历史记录

旧版非 Codex 类型和桥接中转的记录、加密密钥、账户查询设置及用量历史原样保留，不会因旧记录而在启动时删除数据、自动转换协议或应用中转。详情显示“需重新配置”，不能直接应用。编辑时保留原地址、密钥、名称及账户信息，提示确认上游支持 Responses，可直接使用内置默认，或重新获取模型并选择默认项后保存，默认强度可选。取消编辑不会修改原记录。旧版本地模型桥接不再启动；若当前 Codex 配置仍指向旧桥接地址，需应用一个支持 Responses 的中转后再使用。旧本地桥接地址和本地凭据不能作为上游中转导入。

### 地址、统计与缓存

API 地址保留完整路径，末尾 `/v1`、自定义版本路径及根路径均不自动增删；获取模型、连通性测试和 Codex 调用使用同一基础地址。通常应填写中转提供的完整 `/v1` 地址。旧版已裁剪的记录会恢复原先模型查询使用的 `/v1` 路径，当前生效文件保持不动，重新应用时才写入修复后的地址；旧地址仍可用于识别“使用中”。余额查询单独提取站点根地址。余额查询默认关闭，开启后必须明确选择 NewAPI 或 Sub2API，再填写对应参数；查询与连通性测试都只使用所选类型，不自动探测或切换。NewAPI 可使用 API 调用密钥读取账户额度；填写账户访问令牌时，必须同时填写纯数字用户 ID，可按站点调整额度换算值。Sub2API 使用 API 调用密钥查询，也可填写账户令牌优先读取账户余额，不显示 NewAPI 专用字段。统计网站与模型 API 地址不同时可单独填写。旧版自动识别配置升级后关闭余额查询，已有明确类型的配置保留。余额接口不可用时显示查询状态，不影响模型调用或本地记录统计。

提示词缓存采用统一策略，不提供开关：依赖中转或模型服务的自动提示词缓存，不在本机缓存完整回答、提示词或工具执行结果。Codex 的 Responses 请求直接发送给中转，本应用不拦截或改写原生缓存字段。命中可能降低重复输入的费用与延迟，但不减少实际输出 Token；支持范围、优惠、前缀长度及有效期由中转决定，不保证命中。真实缓存读取、写入及命中率继续来自中转用量统计，不将未知值当作 0，不把写入量当作读取命中，也不伪造节省量。

发布的源码压缩包不包含生成的 EXE、真实 Codex 配置、API 密钥、本机缓存或运行时依赖包。在本地构建或测试后，项目内会生成 `build/` 和 Python 缓存目录。

## 窗口状态

窗口会自动记住上次调整后的大小、位置和最大化状态，完全退出后重新运行也会恢复；最小化和静默启动不会覆盖正常窗口尺寸。从托盘恢复时保留此前的最大化状态。偏好存放于应用数据目录的 `window-state.json`，与中转和 Codex 配置独立；断开显示器或改变屏幕布局后会调整到可见工作区，偏好损坏或首次运行时使用默认窗口。

## 内存管理

详情响应缓存最多保留 24 份，序列化 UTF-16 数据预算为 4 MiB，单份上限为 1 MiB；这些是缓存数据预算，并非进程实际堆内存上限。本地查询按日期、模型共用缓存，并按最近使用顺序淘汰；切换会话数据目录后丢弃旧目录缓存，避免混用。磁盘快照在页面初始化时读取，查询响应不再重复携带本地历史。关闭窗口只收起到托盘，不销毁或重新加载 WebView2，重开保留原页面、筛选和未保存草稿，因此后台会保留界面内存。隐藏时由原生定时器调度余额及本地记录刷新，避免与前台定时器重复执行；模型调用由 Codex 直接连接上游，不依赖本应用运行。收起时释放空闲会话服务，定时读取或后续操作按需启动；完全退出请右键托盘图标选择“退出”。

接口响应直接使用现有缓冲区解码，用量汇总减少临时集合；超过 256 条的 NewAPI 日志在后台线程处理。会话列表每次刷新只扫描一次本地数据，长会话预览共享去重集合，仅保留当前分页和最近一次可重试响应，避免旧分页持续累积。

## 验证

运行 `tests/test-window-placement.ps1 -ToolchainRoot <依赖目录>` 验证窗口状态读取、屏幕边界校验，以及独立进程之间的普通窗口、最大化、最小化和静默启动恢复。测试仅使用 build 内的独立偏好文件，不接触实际用户的窗口设置。

运行 `tests/test-codex-provider.ps1 -ToolchainRoot <依赖目录>` 验证 Codex / Responses 限制、内置默认与自定义模型模式、默认推理强度、完整模型列表、密钥隔离、旧数据保留与显式迁移、配置应用和导入，并验证旧模型目录升级、加密备份恢复与外部文件隔离。通过本机 Codex CLI 验证完整模型目录、六档强度和显示名，以及 Responses 模拟接口上的真实 Token 通知（272000 × 95% = 258400）、请求强度覆盖默认项、独立预算覆盖、空会话和未返回用量；另验证 Sol 使用普通模型 ID 和预算，不再额外添加 500k 预设。可通过 `-CodexPath` 指定 CLI，或用 `-SkipCli` 只运行原生回归。测试使用 build 内的独立配置与合成密钥，不访问真实模型服务或修改用户的 Codex 配置；实际服务可用性需用户自己的 API 密钥验证。

运行 `node --test tests/detail-cache.test.cjs` 验证缓存淘汰、容量计算及大量查询下的数据保留上限。

使用会话虚拟环境运行 `python tests/measure-memory.py "build/current/Codex Relay Lite.exe"`，可执行隔离桌面 smoke 并采样主程序及全部子进程的工作集和私有内存，结果写入对应构建目录的 `smoke-data/process-memory.json`。工作集合计可能包含共享页，不能直接当作唯一物理内存用量。

使用会话虚拟环境运行 `python -m pytest session-backend/tests -q`。桌面测试先运行 `python tests/seed-session-fixture.py` 创建 `build/current/smoke-data/` 内的合成会话，再执行 `build/current/Codex Relay Lite.exe --smoke-test`；运行 `node tests/generate-fixtures.cjs` 后，可通过 `build/current/Codex Relay Lite.exe --self-test` 验证原有中转逻辑。夹具默认写入同一当前构建目录，验证后清理临时产物。期望值来自独立旧版参考快照，生成时仅平移日期，无需其他项目目录。测试不操作真实用户会话。
